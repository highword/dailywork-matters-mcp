Create directory `.github/workflows/` if it doesn't exist, then create `.github/workflows/ci.yml` with this exact content (per D-08):

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
        node-version: [20.x]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'pnpm'
      - run: pnpm install
      - run: pnpm build
      - run: pnpm test -- --run
```

Notes on choices:
- `fail-fast: false` ensures all platforms report even if one fails early
- `actions/checkout@v4` is the current stable (v6 in RESEARCH.md was speculative; v4 is verified stable)
- `pnpm/action-setup@v4` auto-detects pnpm version from packageManager field or latest
- Node 20.x is LTS and matches the project's `target: 'node18'` minimum
- `pnpm test -- --run` runs vitest in single-run mode (no watch)

Create `.github/workflows/publish.yml` with this exact content (per D-10):

```yaml
name: Publish

on:
  push:
    tags:
      - 'v*'

jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20.x'
          registry-url: 'https://registry.npmjs.org'
          cache: 'pnpm'
      - run: pnpm install
      - run: pnpm build
      - run: pnpm test -- --run
      - run: npm publish --provenance --access public
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

Notes on choices:
- `permissions.id-token: write` is required for npm provenance (OIDC)
- `registry-url` must be set for `setup-node` to configure .npmrc for auth
- Uses `npm publish` (not `pnpm publish`) because npm provenance flag is more reliable
- `--access public` is required for scoped packages or first publish of unscoped packages
- `secrets.NPM_TOKEN` must be configured in repo settings (this is a human-action but noted as user_setup, not a plan task)
- Build + test runs again in publish workflow to ensure tag commit is clean
