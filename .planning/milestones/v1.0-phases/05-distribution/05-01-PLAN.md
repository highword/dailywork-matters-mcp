**logger.ts** — Replace the entire file with pino synchronous destination mode (per D-03, fixes Pitfall 1):
```typescript
import pino from 'pino';

export const logger = pino(
  { level: process.env.LOG_LEVEL || 'info' },
  pino.destination({ dest: 2, sync: true })
);
```
This removes the `transport: { target: 'pino/file' }` that spawns worker threads (unbundleable). The `dest: 2` writes to stderr (fd 2), `sync: true` means no worker thread. The exported `logger` interface is unchanged — all existing imports continue to work.

**main.ts** — Fix static asset path resolution (per Pitfall 2, fixes 404s via npx):

1. Add imports at top:
```typescript
import { fileURLToPath } from 'node:url';
```

2. Replace the `uiDistPath` resolution block (lines ~45-46):
```typescript
// OLD: const uiDistPath = path.resolve(process.cwd(), 'dist/ui');
// NEW: resolve relative to this script's location (works via npx)
const __dirname = path.dirname(fileURLToPath(import.meta.url));
const uiDistPath = path.resolve(__dirname, 'ui');
```
After bundling, `dist/server.mjs` and `dist/ui/` are siblings, so `path.resolve(__dirname, 'ui')` correctly finds the UI assets regardless of the user's working directory.

3. Update the `serveStatic` call to use absolute path:
```typescript
app.use('/*', serveStatic({ root: uiDistPath }));
```
Replace the relative `'./dist/ui'` with the absolute `uiDistPath` variable. The `@hono/node-server` `serveStatic` accepts an absolute `root` path.
