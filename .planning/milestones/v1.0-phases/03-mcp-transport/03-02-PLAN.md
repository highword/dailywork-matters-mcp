# Plan 03-02: MCP Tool Registration (6 tools)

<objective>
Register all 6 MCP tools with the server using the registerTool API. Each tool has Zod input validation, proper error handling (isError: true), and calls the intelligence/persistence layers from Plans 02-* and 03-01.

Purpose: These are the primary user-facing interface. Host AIs call these tools to generate, retrieve, and manage summaries.
Output: 7 files (6 tool modules + 1 index) completing the MCP tool layer.
</objective>

<tasks>

<task id="1">
<title>Implement generate_daily_summary and save_summary tools</title>
<read_first>
- src/server/intelligence/index.ts (generateSummary API)
- src/server/intelligence/types.ts (GenerateSummaryResult)
- src/server/persistence.ts (saveSummaryFile)
- src/server/adapters/registry.ts (gatherEvents)
- src/shared/paths.ts (createDateRange)
- .planning/phases/03-mcp-transport/03-CONTEXT.md (D-01, D-02)
- .planning/phases/03-mcp-transport/03-RESEARCH.md (Section 1, 6, 7)
</read_first>
<action>
**Step A:** Create `src/server/mcp/tools/generate-daily-summary.ts`:

Register tool `generate_daily_summary` with:
- Input: `{ date?: string }` (optional, defaults to today)
- Logic: Create DateRange → gather events from registry → call generateSummary → if API mode: saveSummaryFile + store in DB → return JSON with summary + file path. If zero-config: return ZeroConfigResponse directly (no file save).
- Error: Return isError: true on failures

**Step B:** Create `src/server/mcp/tools/save-summary.ts`:

Register tool `save_summary` with:
- Input: `{ date: string, markdown: string }`
- Logic: Call saveSummaryFile → store in DB with mode='zero-config' → return confirmation with file path
- This enables zero-config two-step pattern (D-02)
</action>
<acceptance_criteria>
- generate_daily_summary defaults to today if no date provided
- generate_daily_summary returns JSON with { summary, file } in API mode
- generate_daily_summary returns ZeroConfigResponse in zero-config mode (no file)
- save_summary accepts date + markdown, saves file, stores in DB
- Both tools use registerTool with Zod schemas
- `pnpm exec tsc --noEmit` passes
</acceptance_criteria>
</task>

<task id="3">
<title>Implement generate_batch_summary with concurrency control</title>
<read_first>
- src/server/mcp/tools/generate-daily-summary.ts (single-day pattern)
- src/server/persistence.ts
- src/server/intelligence/index.ts
- .planning/phases/03-mcp-transport/03-CONTEXT.md (D-11, D-12, D-13)
- .planning/phases/03-mcp-transport/03-RESEARCH.md (Section 5: Concurrency)
</read_first>
<action>
Create `src/server/mcp/tools/generate-batch-summary.ts`:
- Input: `{ startDate: string, endDate: string }`
- Logic: Generate date range → filter out dates with no data → process with max 3 concurrency → collect results
- Concurrency: Inline Promise-pool pattern (no external dependency)
- Skip logic: Check if date has any events via adapter discovery. Skip dates with zero events.
- Regenerate: Process all dates that have data, even if summary already exists (D-12)
- Return: `{ processed: N, skipped: M, failed: K, results: [...] }` (D-13)
</action>
<acceptance_criteria>
- Tool accepts startDate and endDate, validates format
- Processes at most 3 dates concurrently
- Skips dates with no session/git data
- Regenerates dates that already have summaries (version append via saveSummaryFile)
- Returns structured result with processed/skipped/failed counts
- `pnpm exec tsc --noEmit` passes
</acceptance_criteria>
</task>
