# Phase 4.1: Zero-Config UI Hint - Research

**Researched:** 2026-06-01
**Domain:** React UI (modal dialog, config detection, navigation)
**Confidence:** HIGH

## Summary

This phase is a small, self-contained frontend change: intercept the Generate button click, check for API key presence via the existing `useConfig()` hook, and show a blocking modal dialog if no key is configured. All infrastructure already exists -- the dialog component, config hook, and navigation patterns are established in prior phases.

The implementation touches exactly one component (`generate-form.tsx`) and adds one new component (the modal content). No backend changes, no new dependencies, no architectural decisions needed. The entire phase is a single plan.

**Primary recommendation:** Add API key check in `handleGenerate`, show existing Dialog component with "Go to Settings" navigation. Total change is ~40 lines across 1-2 files.

### Pattern 1: Config Check at Click Time (D-05)

**What:** Check cached config data synchronously when user clicks Generate
**When to use:** When blocking an action based on config state

```typescript
// Source: Existing useConfig hook + project patterns
import { useConfig } from '../../hooks/use-config';

export function GenerateForm({ onGenerate, isGenerating }: GenerateFormProps) {
  const { data: config } = useConfig();
  const [showApiKeyDialog, setShowApiKeyDialog] = useState(false);

  const handleGenerate = () => {
    // D-01: Check before SSE request
    if (!config?.ai?.apiKey) {
      setShowApiKeyDialog(true);
      return; // Block generation
    }
    const dateStr = format(selectedDate, 'yyyy-MM-dd');
    onGenerate(dateStr);
  };
  // ...
}
```

**Key insight:** `useConfig()` data is cached by TanStack Query (staleTime: 30s per main.tsx). The config is already fetched when the Generate page loads (Settings page or any prior navigation triggers it). The check is effectively synchronous against cached data. ### Anti-Patterns to Avoid

- **Fetching config on every click:** Don't make a fresh API call on click. Use the cached TanStack Query data (`useConfig().data`). The cache is already warm.
- **Disabling the button at page load:** D-05 explicitly states detection at click time. Don't grey out the button or show warnings before the user interacts.
- **Modifying backend/SSE endpoint:** D-01 blocks the request before it's sent. The backend `generate.ts` remains unchanged.

## Common Pitfalls

### Pitfall 1: Config Not Yet Loaded on First Visit

**What goes wrong:** User navigates directly to /generate as first page load. `useConfig()` returns `{ data: undefined, isLoading: true }` for a brief moment. If they click Generate instantly, `config?.ai?.apiKey` evaluates as falsy, showing the modal even if a key IS configured.
**Why it happens:** TanStack Query hasn't completed the initial fetch yet.
**How to avoid:** The check `!config?.ai?.apiKey` is conservative -- it will show the modal. This is acceptable because: (a) the fetch completes in <50ms for a local server, (b) the Generate button shows loading state during generation anyway, (c) showing the modal falsely once is a minor UX hiccup, not a functional error. Alternatively, also check `if (!config) return;` to do nothing while config is loading.
**Warning signs:** Modal flashes on first click then disappears after config loads.
**Recommendation:** Guard with `if (!config) return;` -- effectively a no-op while loading. TanStack Query will have the data within milliseconds for a localhost API.

### Pitfall 2: Dialog Stays Open After Navigating Back

**What goes wrong:** User clicks "Go to Settings", then uses browser back button. The dialog state `showApiKeyDialog` might still be true in the component's React state if the component wasn't unmounted.
**Why it happens:** React Router with lazy loading may keep the generate page component mounted in memory.
**How to avoid:** React Router lazy routes DO unmount when navigating away (verified by the `lazy: () => import(...)` pattern in main.tsx). State resets on re-mount. This is a non-issue.
**Warning signs:** Dialog visible when returning to Generate page after configuring the key.

### Pitfall 3: Stale Config After Setting API Key

**What goes wrong:** User sets API key in Settings, navigates back to Generate, but TanStack Query cache still has the old config (no apiKey).
**Why it happens:** `useUpdateConfig` in settings-form.tsx already calls `queryClient.invalidateQueries({ queryKey: ['config'] })` on success. However, the staleTime is 30s.
**How to avoid:** The invalidation in `useUpdateConfig` forces a refetch on next access regardless of staleTime. This is already handled correctly.
**Warning signs:** None expected -- existing invalidation logic covers this.

```typescript
// Source: Project codebase analysis -- composed from existing patterns
import { useState } from 'react';
import { useNavigate } from 'react-router';
import { format } from 'date-fns';
import { CalendarIcon, KeyRound, Loader2 } from 'lucide-react';
import { Button } from '../ui/button';
import { Calendar } from '../ui/calendar';
import { Popover, PopoverContent, PopoverTrigger } from '../ui/popover';
import {
  Dialog, DialogContent, DialogHeader, DialogTitle,
  DialogDescription, DialogFooter,
} from '../ui/dialog';
import { useConfig } from '../../hooks/use-config';
import { cn } from '../../lib/utils';

interface GenerateFormProps {
  onGenerate: (date: string) => void;
  isGenerating: boolean;
}

export function GenerateForm({ onGenerate, isGenerating }: GenerateFormProps) {
  const [selectedDate, setSelectedDate] = useState<Date>(new Date());
  const [showApiKeyDialog, setShowApiKeyDialog] = useState(false);
  const { data: config } = useConfig();
  const navigate = useNavigate();

  const handleGenerate = () => {
    // D-05: Check at click time, not page load
    if (!config) return; // Config still loading -- no-op
    if (!config.ai?.apiKey) {
      setShowApiKeyDialog(true);
      return; // D-01: Block SSE request
    }
    const dateStr = format(selectedDate, 'yyyy-MM-dd');
    onGenerate(dateStr);
  };

  return (
    <div className="space-y-4">
      {/* ... existing calendar picker unchanged ... */}

      <Button onClick={handleGenerate} disabled={isGenerating} className="mt-4">
        {isGenerating ? (
          <>
            <Loader2 className="h-4 w-4 animate-spin" />
            Generating...
          </>
        ) : (
          'Generate Summary'
        )}
      </Button>

      {/* D-07: Existing dialog component, D-02: fully blocks */}
      <Dialog open={showApiKeyDialog} onOpenChange={setShowApiKeyDialog}>
        <DialogContent>
          <DialogHeader>
            <DialogTitle>API Key Required</DialogTitle>
            <DialogDescription>
              An API key is needed to generate AI-powered summaries.
              Configure one in Settings to get started.
            </DialogDescription>
          </DialogHeader>
          <DialogFooter>
            <Button variant="outline" onClick={() => setShowApiKeyDialog(false)}>
              Close
            </Button>
            <Button onClick={() => navigate('/settings')}>
              Go to Settings
            </Button>
          </DialogFooter>
        </DialogContent>
      </Dialog>
    </div>
  );
}
```
