# Phase 4.1: Zero-Config UI Hint — Context

**Gathered:** 2026-06-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Generate page in the Web UI detects zero-config mode (no API key configured) and blocks generation with a modal dialog explaining the situation. This is a frontend-only change — no backend modification needed. The MCP tool `generate_daily_summary` continues to work normally in zero-config mode (host AI consumes raw data).

</domain>

<decisions>
## Implementation Decisions

### Trigger Behavior
- **D-01:** Generate button click checks config for API key presence **before** sending the SSE request. If no key → show modal, do NOT call `/api/generate`.
- **D-02:** The modal **fully blocks** generation in Web UI. No "proceed anyway" option — raw event data is meaningless without a host AI to consume it.
- **D-03:** MCP tools remain unaffected. `generate_daily_summary` in zero-config mode still returns `ZeroConfigResponse` for host AI consumption.

### Detection Mechanism
- **D-04:** Frontend reads config via the existing `/api/config` endpoint (already used by Settings page). Check `config.ai.apiKey` presence.
- **D-05:** Detection happens at click time (not page load). User sees the normal Generate page UI, clicks Generate, and THEN gets the modal if unconfigured.

### Modal Content & Design
- **D-06:** English text only. One concise sentence + "Go to Settings" button.
- **D-07:** Use existing `dialog.tsx` component (custom portal-free implementation from Phase 4).
- **D-08:** Modal has two actions: "Go to Settings" (navigates to /settings) and "Close" (dismisses modal, stays on Generate page).

### Claude's Discretion
- Exact wording of the prompt message
- Modal styling details (icon choice, color accent)
- Whether to add a subtle visual indicator on the Generate page header when in zero-config mode

</decisions>
