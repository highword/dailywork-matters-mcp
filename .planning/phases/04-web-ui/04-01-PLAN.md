Create 5 files implementing the REST API per D-15, D-16, D-17, D-18:

**src/server/api/summaries.ts:**
- Export `summariesRoutes` as `new Hono()`
- `GET /` — call `loadConfig()`, `resolveConfigPaths()`, `listSummaryDates(config.outputDir)`, return `c.json({ dates })` (string[] sorted newest first)
- `GET /:date` — validate date with regex `/^\d{4}-\d{2}-\d{2}$/` + `!isNaN(Date.parse(date))`. If invalid return 400 `{ error: { code: 'INVALID_PARAMS', message: 'Invalid date format. Expected YYYY-MM-DD.' } }`. Query DB: `SELECT * FROM summaries WHERE date = ? ORDER BY version DESC LIMIT 1`. If no row, return 404 `{ error: { code: 'NOT_FOUND', message: 'No summary for {date}' } }`. If found, return `{ date, version, summary: JSON.parse(structured_json), markdown, metadata: JSON.parse(metadata) }`
- Import from: `../database.js`, `../persistence.js`, `../config.js`, `../logger.js`

**src/server/api/generate.ts:**
- Export `generateRoutes` as `new Hono()`
- `POST /generate` — parse body `{ date?: string }`. Default to today (formatToday helper). Validate date. Use `streamSSE` from `hono/streaming` per D-16.
- SSE event sequence: `progress` (stage: 'gathering'), gather events via `registry.gatherEvents(range)`, `progress` (stage: 'processing'), call `generateSummary()`, if API mode save file + insert DB (same pattern as MCP tool), `complete` event with `{ date, summary }`. On error: `error` event with `{ code, message }`.
- The handler needs access to `config` and `registry`. Accept them via a factory function: `export function createGenerateRoutes(config: Config, registry: AdapterRegistry): Hono`. This is necessary because the generate endpoint needs the adapter registry and resolved config that are created during server startup.

**src/server/api/stats.ts:**
- Export `statsRoutes` as `new Hono()`
- All endpoints require `?from=YYYY-MM-DD&to=YYYY-MM-DD` query params. Validate both. On invalid: 400.
- `GET /categories` — SQL: `SELECT t.category, SUM(t.time_proportion) as total_proportion, COUNT(*) as task_count FROM tasks t JOIN summaries s ON t.summary_id = s.id WHERE s.date BETWEEN ? AND ? GROUP BY t.category ORDER BY total_proportion DESC`
- `GET /trends` — SQL: `SELECT s.date, COUNT(t.id) as task_count FROM summaries s JOIN tasks t ON t.summary_id = s.id WHERE s.date BETWEEN ? AND ? GROUP BY s.date ORDER BY s.date`
- `GET /files` — SQL: `SELECT t.files FROM tasks t JOIN summaries s ON t.summary_id = s.id WHERE s.date BETWEEN ? AND ?` then parse JSON arrays, count file occurrences, return top 20 sorted by count
- `GET /hours` — SQL: `SELECT s.date, s.created_at FROM summaries s WHERE s.date BETWEEN ? AND ?` (for work hours distribution — return the created_at times grouped by hour)
- `GET /heatmap` — SQL: `SELECT s.date, COUNT(t.id) as task_count FROM summaries s LEFT JOIN tasks t ON t.summary_id = s.id WHERE s.date BETWEEN ? AND ? GROUP BY s.date`
- `GET /projects` — SQL: `SELECT t.metadata FROM tasks t JOIN summaries s ON t.summary_id = s.id WHERE s.date BETWEEN ? AND ?` — no, better: parse structured_json.metadata.projects. Actually use: `SELECT s.date, s.metadata FROM summaries s WHERE s.date BETWEEN ? AND ?` then extract projects array from each metadata JSON, aggregate project -> task_count.
- All responses: `c.json({ data: [...] })`

**src/server/api/config.ts:**

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> API | User input (date params, config body) crosses into server-side processing |
| API -> Filesystem | Date param used to construct file paths (path traversal risk) |
| API -> SQLite | Query params used in SQL (injection risk) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | /api/summaries/:date | mitigate | Validate date with strict regex `/^\d{4}-\d{2}-\d{2}$/` + Date.parse check before any filesystem/DB access |
| T-04-02 | Tampering | /api/stats/* | mitigate | Validate from/to query params with same date regex; use parameterized SQL (prepare + bind) not string interpolation |
| T-04-03 | Tampering | PUT /api/config | mitigate | Only accept known Config fields; saveConfig merges with existing (unknown fields ignored by spread) |
| T-04-04 | Information Disclosure | /api/config | accept | localhost-only tool; API key visible to local user who already has filesystem access |
| T-04-05 | Denial of Service | POST /api/summaries/generate | accept | Single-user local tool; no rate limiting needed |
</threat_model>
